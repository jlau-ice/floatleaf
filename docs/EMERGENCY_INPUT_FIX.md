# 按键状态不可读时的紧急隐藏

日期：2026-10-18。当前源码准备 v0.2.5；已发布 v0.2.4 尚不包含此修复。

## 问题与改动

全局快捷键事件先经过已注册组合键匹配。此前紧急隐藏与翻页共用同一个条件：收到 Pressed，且当下完整组合键采样为 true。Windows 跨权限读取或 macOS 未授权后台读取时，可能出现事件已收到但采样为 false，紧急隐藏因此未执行。即使没有权限限制，事件处理前主键已经松开也会触发此边界。

紧急隐藏现在只需要收到已注册的 Pressed 事件，不再依赖采样或之前的释放是否被看到；它只会隐藏，不会显示内容。同时暂停自动阅读，与设置按钮一致。复查发现托盘原本只隐藏、保留自动阅读开关，现改为复用已有的 `hide` 操作，统一暂停行为。显示、翻页与自动阅读开关继续要求有效采样。紧急隐藏后仍需完整释放显示组合键，旧事件不能重新显示。

抽出已有快捷键状态转换为同模块函数，供实际回调与单元测试共同使用；未增加通用抽象、依赖、钩子或提权路径。注册/事件日志补充配置快捷键的 `keyId`，用于对应系统消息，不记录其他输入。

## 验证证据

- 新增回归在旧逻辑下明确失败：`Hold must hide on the event`，记录 `.local/emergency-input/before.log`。修复后三种显示模式全部通过，覆盖采样全 false、暂停自动阅读、旧组合键保持隐藏、全松后恢复和丢失紧急键释放事件后再次隐藏。
- 另一回归确认采样不可用时显示、翻页及自动阅读不会误触发，单独 Released 不会当作紧急隐藏。当前本机 29 项 Rust 测试、类型/rustfmt/Clippy 与 Windows 目标 release Clippy 通过。
- macOS debug app 实际构建和启动、独立合成书库导入/固定显示/自动阅读通过。自动化发送的组合键没有立即得到全局事件，不计为快捷键通过；后续混入用户按键的旧进程日志单独保留，不用作受控对照。
- 新修复调试进程 PID 24227 使用独立书库，输入权限 false；临时紧急键 Ctrl + Option + E 尚无事件证据。用户添加权限并报告仍未授权后，核对实际运行的是旧发布包 `.local/release-024/mac-trial/FloatLeaf.app`（PID 25942），并非所添加的调试包。正常退出旧包，以 `open -n --env ...` 指定调试 app 路径重新启动 PID 26295，权限 IPC 返回 true、界面权限提示消失；没有重新编译或修改系统权限。默认快捷键恢复后，用户确认后台显示、松键隐藏正常；日志核对五组按下/释放，后台权限 true、按下主键/组合键 true 并显示、主键释放后隐藏。证据 `.local/emergency-input/mac-after-permission.json`。测试设置不影响用户原书库或日常快捷键；本包含紧急隐藏修复，但保留构建时版本 0.2.4，不能记为最终 0.2.5 包验收。
- Windows 普通安装包脚本增加六项原生断言：显示组合键仍按着、紧急主键未按下时，向当前应用的已注册快捷键窗口投递 `WM_HOTKEY`；核对实际隐藏、不抢焦点、事件采样、旧组合键保护和重新触发。这是普通包的消息时序注入，不伪称跨权限或物理键鼠验收；CI 待执行。

本轮证据在忽略目录 `.local/emergency-input/`。Windows 11 拼多多实际权限场景、macOS 物理输入与新安装包仍分别记录，不能用单元测试替代。
